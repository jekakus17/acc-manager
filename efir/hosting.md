# Хостинг, сервер и три способа заливки

Материал к первому блоку эфира. Отвечает на вопрос, который в чате прозвучит
обязательно: «а в чём разница между хостингом и сервером и что мне брать».

---

## 1. Главное различие одной фразой

> **Хостинг показывает файлы. Сервер выполняет программы.**

Всё остальное — следствия. Держите эту фразу в голове, она же будет мостиком
ко второму блоку про бота.

---

## 2. Три типа площадок

### A. Обычный хостинг — reg.ru, Beget, Timeweb

Кусочек чужого сервера, где всё уже настроено. Вам выдали папку `public_html`
и панель управления. Кладёте файлы — они открываются в браузере.

| | |
|---|---|
| Что уже настроено | Веб-сервер, SSL в один клик, бэкапы, защита от нагрузок |
| Что делаете вы | Только загружаете файлы |
| Кто вы там | Квартирант: своё ПО поставить нельзя |
| Цена | 150–400 ₽/мес |
| Порог входа | Нулевой |
| Для чего | Лендинги, сайты-визитки, WordPress, интернет-магазины на готовых движках |

**Чего там нельзя:** запустить телеграм-бота, поставить n8n, поднять докер,
крутить постоянно работающую программу. На части тарифов есть Node.js и Python,
но это всегда с ограничениями — полноценно программа там не живёт.

### B. Статик-хостинги — Netlify, Vercel, GitHub Pages, Cloudflare Pages

Отдельная категория, про которую мало кто знает. Заливаете сайт через гит —
он публикуется сам, автоматически, за секунды.

| | |
|---|---|
| Цена | Бесплатно для одного сайта |
| Деплой | Пуш в репозиторий → сайт обновился сам |
| SSL | Автоматически |
| Ограничение | Только статика: HTML, CSS, картинки. Программу не запустить |
| Минус | Нужен гит и минимальное понимание, как он работает |

**Кому:** тем, кто готов один раз разобраться с гитом. Дальше правки
выкатываются одной командой, без файловых менеджеров вообще.

### C. Свой сервер — VPS или VDS

Виртуальная машина с чистой Ubuntu, где вы администратор. Пустая коробка:
что поставите, то и будет работать.

| | |
|---|---|
| Что настроено | Ничего. Голая операционная система |
| Что делаете вы | Ставите веб-сервер, выпускаете SSL, обновляете, следите за безопасностью |
| Кто вы там | Хозяин: можно всё |
| Цена | 300–1500 ₽/мес |
| Порог входа | Несколько часов на первую настройку. С нейросетью — вечер |
| Для чего | Боты, n8n, автоматизации, базы данных, всё, что должно работать 24/7 |

**Где брать:** reg.ru, Timeweb Cloud, Selectel, Beget — у всех есть VPS.
Это отдельный продукт, не тот тариф, где лежит сайт.

## 4. Что кому советовать (готовый ответ на вопрос из чата)

> «Если у вас только сайт — берите обычный хостинг и не думайте. Двести рублей
> в месяц, ноль головной боли.
>
> Если готовы один раз разобраться с гитом — статик-хостинг бесплатно
> и правки выкатываются автоматически.
>
> Сервер нужен ровно в одном случае: когда у вас появляется что-то, что должно
> работать постоянно. Бот, автоматизация, интеграция. Не берите сервер
> заранее — возьмёте, когда упрётесь.»

## 5. Три способа заливки — лестница автоматизации

### Способ 1. Руками

Файловый менеджер в панели или FileZilla по FTP.

**Плюс:** работает всегда и везде, понятно любому.
**Минус:** каждая правка — ручной цикл: скачал, поправил, залил, обновил.

**Что показать на эфире:** заливку файла в `public_html` и обновление страницы.

### Способ 2. Дать доступ нейросети

Здесь важная развилка, которую надо проговорить честно:

> **Прямого доступа к панели хостинга у нейросети нет.** В браузерном чате
> вы не «дадите ей доступ к reg.ru» — там просто нет такого механизма.

Реально работают два пути:

**2a. Агент с терминалом** — Claude Code, Cursor, Windsurf.
Кладёте в проект одну команду синхронизации по FTP, дальше говорите «залей».
Агент выполняет и отчитывается.

```
lftp -c "open -u ЛОГИН,ПАРОЛЬ ftp.вашдомен.ру; \
  mirror -R --delete ./site /public_html"
```

Один раз настроили — дальше деплой голосом.

**2b. Через гит** — надёжнее и на эфире выглядит эффектнее.
Правка → коммит → пуш → сайт обновился сам. На статик-хостингах это работает
из коробки, на обычном хостинге настраивается через автодеплой в панели
(на reg.ru и Beget такое есть).

**Про безопасность — обязательно скажите вслух:**
- не вставляйте FTP-пароль в чат браузерной нейросети
- заведите отдельный FTP-аккаунт с доступом только к `public_html`
- если что-то утечёт, потери ограничены одной папкой, а не всем хостингом

### Способ 3. Свой сервер

SSH-ключ, и агент деплоит сам одной командой. Максимум свободы, максимум
ответственности: за обновления и безопасность отвечаете вы.

## 6. «Что именно заливать после правок»

Приём, который стоит показать: попросите модель в конце каждого ответа
отдавать список изменённых файлов.

```
После правок в конце ответа всегда пиши список файлов,
которые нужно перезалить на хостинг. Только имена файлов, списком.
```

Пока сайт — один `index.html`, ответ всегда один и тот же. Как только
появятся картинки, отдельный CSS или вторая страница — список перестанет
быть очевидным, и привычка спрашивать окупится.

**Правило для эфира:** заливаем только те файлы, которые менялись.
Перезаливать весь сайт целиком каждый раз — не ошибка, но долго
и однажды затрёт то, что правили прямо на сервере.

## 7. Заготовки на вопросы из чата

**«А домен где брать, там же?»**
> Обычно у того же провайдера — так проще, привязка делается сама.
> Можно и в другом месте, тогда прописываете DNS руками.

**«Сколько всего в год выходит?»**
> Домен в зоне .ru — около 200–300 ₽ в год, хостинг — от 2000 ₽ в год.
> Итого сайт стоит примерно как две чашки кофе в месяц.

**«Меня взломают?»**
> Статический сайт взламывать нечего — это просто файл, там нет ни базы,
> ни админки. Риски начинаются с WordPress и с собственного сервера.

**«А если хостинг упадёт?»**
> Держите копию файла у себя. Сайт из одного файла переезжает
> на другой хостинг за десять минут.

**«Можно вообще без хостинга?»**
> На статик-хостингах — да, бесплатно. Но домен всё равно платный,
> иначе адрес будет вида `имя.netlify.app`.
